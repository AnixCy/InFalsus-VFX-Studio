# 本体轨道网点与按键文字视觉还原方案

依据：本机 `InFalsusModded1.07b` 的 GameScene、原始贴图、字体资产、GPU 程序和 IL2CPP 方法。日期：2026-10-29。目标制谱器：当前 InFalsus Studio+ 1.0.7。

本文件为开发方案。没有修改制谱器源码、配置、副本或 release。用户提供的两张图只用于识别要研究的部位，没有从图中取色、裁图、测量坐标或制作素材。

用户随后打开本体并暂停。本轮已对该本体进程做只读采集：六轨 FastText 的真实字号/颜色/Bounds、六条 Letter 父链，以及四轨 Renderer 的实际材质实例引用。没有调用、注入或改写游戏函数。

## 1. 调查结论与实施边界

两项要分别处理：

1. **上方轨道网点：恢复原始轨道材质的纹理、几何映射和采样条件。** 点阵已经包含在本体轨道图集中，当前制谱器也确实包含同一张原图，不能再随手叠加一张噪声图。需要核对的是图集在世界中的位置、运行时材质选择、采样及颜色合成；截图中较密集的云状观感目前没有被证实为一个独立特效对象，不能给它编造粒子数量、颜色或移动速度。
2. **下方按键文字：替换当前 GUI.Label 实现。** 本体使用原生 FastText、UD 新ゴ DeBold 字体、HDR 青色和三维父子变换；当前制谱器继承微软雅黑 UI，用屏幕字号和固定侧轨角度绘制，字形、颜色和位置计算都不同。

实施范围限于中央轨道的可见纹理/文字绘制及新增文字显示设置。现有侧轨面板对位、地面判定线、轨道细线、音符和作者操作应保持原有行为。

### 3.4 当前代码的差异及具体修改方案

`NativeVisualTrack.cs` 当前将每轨横向重新归一到 `Lerp(.015,.985,f)`，相当于把每轨原有横断面再收缩 3%；表面还加了统一 `-.009` 高度偏移。原 UV 虽然保留，但点阵在世界中的位置和采样导数随网格变化。另一方面，底图像素已经相同，不能把这两处差异直接说成截图“密集点群”的唯一原因。

实施顺序：

1. **先做同输入离屏对照。** 原 Material 133 + 原网格/矩阵/UV，与现有中央轨道同时使用同一相机、同一启用状态、相同 shader 全局量和后处理，分别记录后处理前颜色。基准使用本体当前的 **AA=None**，再单独打开编辑器 SMAA 比较，不把两个不同抗锯齿状态混在一起调贴图。此步骤不用用户附图构造素材。
2. **中央可见网格改用原始矩阵映射。** 去掉二次横向收缩，使用上表坐标与原始高度；仅处理可见渲染网格，不改 StageSpace、音符位置或拾取规则。沿用 stageNear/stageFar 裁切，不能把 57.279527 的原图跨度硬拉成 50.454528。
3. **保留原始颜色及 mip 链。** 不改点的密度、颜色或随机种子，不把 Bilinear 改成 Point 来制造明显斑点，不另开高亮噪点层。
4. **核对 Gamma 采样。** 本体是 Gamma，制谱器是 Linear；若确认偏差从纹理过滤/着色阶段产生，用保留原压缩 mip 数据、以 Gamma 编码值进行过滤的私有纹理视图，在输出场景颜色前转换一次至 Linear。不能对已经正确的输出再做第二次 Gamma 转换。是否需要此分支由第 1 步的数值差决定。
5. **保留本体启用/禁用材质语义。** 默认全轨启用时不播放点阵动画。Hit/Whiff 只按本体切换默认/Hit 图，不把它做成常驻亮点。LaneTerminal 纹理 381 及启用状态数组保留原语义，不当作网点噪声使用。

**密集云状观感的验收门槛：** 当帧默认材质和实际 AA 条件已补读，仍没有证据能把云状区域确定为独立噪声材质或粒子，方案不虚构这一层的参数。先用 AA=None 的同输入对照定位差异；若仍存在，再核对实际 GPU 采样/LOD、shader 全局量及后处理阶段输出。只有这一对照能决定第 2～4 步中哪些确实需要实装，不能把所有参数差异都当作已证明的故障原因。保留用户 SMAA 选择时允许其按既有设定平滑点阵，不能为补偿 SMAA 再加噪点。

## 4. 下方六轨按键文字

### 4.1 当前问题出在哪里

制谱器核心 `StudioBootstrap.DrawKeyLabels` 仍使用 `GUI.Label`：

- 字体继承当前 GUI 皮肤，实际为 Microsoft YaHei UI / Microsoft YaHei / Segoe UI，额外 Bold。
- 字号为 `Clamp(Screen.height / 42,14,29)`，例如 1080 高时为 25 px，不是本体 FastText 字号。
- 使用逻辑轨道的 `.5` 中点、`z=.18`、lift `.02`，再投影至 140×40 屏幕文字框。
- 左右侧轨角度固定为屏幕 `+32°/-32°`。
- `GUI.color=(.64,.97,1,.86)` 还乘上皮肤字色 `(.79,.90,.94,1)`，颜色输入乘积变成 `(.5056,.873,.94,.86)`。

这解释了为何贴图已经对位，文字仍偏蓝、字形不对、大小/倾斜不随本体平面变化。当前 `NativeReadability` 只追加判定显示，并没有替换这六个字。

### 4.3 正确颜色及透明度

| 参数 | 精确 RGBA |
| --- | --- |
| `defaultTextColor` / 文字色 | **(1.2691348791122437, 2.3396224975585938, 2.3396224975585938, 0.3607843220233917)** |
| 序列化描边色 | (0.5921568870544434, 0.9921568632125854, 0.9921568632125854, 1)；默认不启用描边 |
| 序列化 bottomColor | (1,1,1,1)；默认无分色时不作为白色渐变输出 |

这是 HDR 浮点颜色。RGB 有分量大于 1，**不能转换成普通 Color32/HEX 后使用**，否则会把 G/B 的 2.3396 截成 1，文字明显变暗或改变色调。

运行时 `KeyPressedIndicator._xl(opacity)` 保留 RGB，将填充 alpha 设为 `0.3607843220233917 × opacity`。Track 正常显示时全局显示因子为 1；对应轨道未启用时另乘 0.3000000119。隐藏模式的因子为 0，特定渐显模式按本体状态钳位到 0～1。不能把这些状态统一变成固定 alpha 0.86。

SDF 片元程序在无描边分支输出：

```text
sourceRGB = 上述 HDR RGB
sourceAlpha = SDF coverage × 0.3607843220233917 × opacity
```

最终画面颜色还取决于底图和混合空间，不能将某一截图像素当成材质 RGB。完整原始字段见 [key-text-evidence.json](visual_research_107b/dots-font-plan/key-text-evidence.json)，原 GPU 状态和反汇编见 [font-shader.json](visual_research_107b/dots-font-plan/font-shader.json)。

### 4.4 六轨位置：使用字体自己的父子矩阵

Letter 不是需要 Constrained2D 重算尺寸的按键面板 quad。其本地 scale=(1,1,1)、rotation=identity；本地位置：中央四轨 `(0,-0.1199999973,0)`，两侧 `(0,-0.05000000075,0)`。

中央父容器：scale=`(0.2000000030,0.1400560439,0.1400560439)`，rotation quaternion=`(0.7071067691,0,0,0.7071067691)`。侧轨父容器：scale=`(0.25,0.1750700474,0.1750700474)`，左右使用各自的 45° 斜面旋转。所有完整链已保存在证据 JSON。

以下是完整父链相乘得到的 **Letter Transform 原点**；不把它冒充某个可见字形像素的中心：

正确的每顶点位置计算为：

```text
p_native = Letter 到 GameCamera 内侧的完整父子矩阵 × FastText 原始字形顶点

```

不能只投影原点后画屏幕正字，也不能把按键面板 quad 的 `(1.8042196,2.4356961,1)` 再乘到文字上。侧轨面板已存在的 `+0.008×k` 微调属于面板对位修复，不应重复叠到 Letter 父链。

矩阵、轴向量和计算用脚本见 [key-anchor-derived.json](visual_research_107b/dots-font-plan/key-anchor-derived.json)、[derive_key_anchors.py](visual_research_107b/dots-font-plan/derive_key_anchors.py)。上表为矩阵计算值；本轮另读取了六条实际运行时父链，每个 Transform 都通过所属 GameObject 校验，与上述位置、旋转和缩放一致，见 [runtime-letter-transforms.json](visual_research_107b/dots-font-plan/runtime-letter-transforms.json)。字形 Bounds 的运行值与 Transform 原点分开记录。

### 4.5 具体渲染与颜色适配方案

1. 从原字体资产保留 OTF、FastText 排版/SDF 度量、原材质参数，生成六个可缓存的字形网格和私有字体图集。不要使用操作系统同名字体替代，也不要在每帧重新栅格化。
2. 独立原生文字 renderer 按上述矩阵放置，保持 queue=3001、LEqual、ZWrite Off。字号变化只由本体宽度公式和字体度量决定，不用 Screen.height/42。
3. 精确拦截旧 `DrawKeyLabels` 的六个 GUI.Label，防止两套字重叠；保留已有 `NativeReadability.DrawJudgements` postfix，不能把判定反馈也一并禁用。
4. 本体为 Gamma、制谱器为 Linear，使用文字专用局部合成，保留浮点 HDR 值。对于覆盖率 c：

```text
a = c × 0.3607843220233917 × opacity
backgroundGamma = LinearToGamma(文字绘制前的完整场景颜色)
resultGamma = backgroundGamma × (1-a) + nativeHDRColor × a
resultLinear = GammaToLinear(resultGamma)
```

5. 字体的底图必须含轨道、面板、细线、判定线及此前应已绘制的透明层。**不能直接复用 `_NativeKeyBackground`**：现有抓取只有不透明舞台和侧墙，复用会在字形范围擦掉面板/细线。可将六个文字放入专用渲染层，从默认透明 pass 排除，在相应透明层完成后、后处理前抓取完整颜色并绘制一次；用 RenderGraph 明确声明输入/输出，不读取陈旧一帧。
6. 私有字体缓冲/材质参数与现有 combo 的 FastText 参数隔离，不用全局覆盖的方式破坏连击数字。
7. 第一轮颜色数值验收以**后处理前**的 Gamma 合成结果为标准。本体 Bloom 参数为 threshold=1.5、intensity=2、scatter=.821；编辑器现值不同。源颜色正确不能被写成最终像素已经相同。最终对照使用匹配后处理的隔离条件；本轮不为文字擅自更改全场景 Bloom 或项目色彩空间。

## 6. 绘制顺序与防回归约束

现有编辑器已经修正过的次序：中央轨道 2000 → 侧墙 2900 → 按键面板 2901 → 轨道细线 2910 → 地面判定线 2920；原生文字材质为 3001。

轨道点阵优先随原轨道材质采样，不增加覆盖在细线/判定线之上的透明粗面。文字合成抓取必须包含此前各层；不能再次用 Blend One Zero 配上不完整底图。字体 renderer 的生命周期随舞台重建/释放，避免重复实例和两套文字残留。

## 7. 后续实施顺序与验收

1. 保存本轮资源指纹及字段，先完成原轨道离屏对照，确定密集纹路差异发生在哪个绘制阶段。
2. 单独恢复中央原始网格/UV/采样条件，核对点阵位置、颜色和密度；不与字体补丁同时盲调。
3. 导入原字体度量及六轨字形网格，先核对无后处理时的顶点、宽度限制和 HDR 合成，再核对最终画面。
4. 接入文字显示开关、共享配置和英文标签。
5. 对照本体相同谱面、同一时刻、相同有效视口；截图只用于此时的结果核对。另检查 16:9 带黑边窗口和自定义相机，防止字号跟整个窗口高度跑偏。
6. 分别确认六轨字形方向、Shift/Space 各自缩放、启用/禁用透明度、正式/非正式预览、重启配置恢复；检查面板、细线、地面判定线未受遮挡。
7. 开关前后核对可见差异只来自六个文字；谱面字节、撤销记录、拾取、滚轮、绿色放置框和天空橙线不受影响。

建议数值门槛：原始纹理/mip 数据指纹一致；本体矩阵到目标坐标的顶点计算误差 ≤1e-5 世界单位；同一相机投影误差 ≤0.25 px；后处理前浮点颜色对照每通道绝对误差 ≤0.005。它们是后续验收要求，本轮进行了只读资源调查、实际本体内存采集和离线矩阵计算，没有实装补丁或宣称执行了这些渲染验收。
