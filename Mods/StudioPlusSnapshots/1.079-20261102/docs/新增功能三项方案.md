# ifstodolist：新增功能三项方案

日期：2026-10-28。依据桌面最新版 `ifstodolist.txt`、当前开发节点 `studio_icon_work/Source`、副本中的 ExternalTools 文档与编辑器核心源码整理。本轮为方案，不执行功能修改、安装或打包。三项均为编辑器作者工具；不新增本体谱面语法。

## 1. SkyArea 共同节点编辑

### 现状与原因

现有首尾把手最终调用 `EndpointDragMode.Endpoint`，操作对象是一个 `SourceId`：修改前一条的尾部时，不会同步后一条的头部。当前中键拖动也只记录一个主拖动对象。因此两条原本相接的 SkyArea 会被单端点拖动拉开。

另一个必须区分的点：`SkyGroups.Joins` 判断的是前后时间差不超过 2 ms、横向区间相交；这用于连接/藏头判断，并不意味着两条的左右边界完全一致。`groupid` 相同也不能证明它们在几何上相接。节点识别不能简单把整组所有物件一起移动。

### 交互方案

- 新增“SkyArea 节点编辑”开关，默认单键 **N**，纳入现有可改热键系统。当前默认键表没有 N；用户自定义冲突时保留已有绑定，仅将新动作设为未绑定并提示。Space/Q/V/Ctrl+R 按本轮已确认的行为保留。
- 首次默认关闭。N 切换后，在选中 SkyArea 的有效相接端显示一个共同节点；只把与所选条目直接相接的候选显示出来，避免满屏控制点。节点位于接触横截面的中点，悬停高亮涉及的两条。
- 节点模式中可以左键选择共同节点并拖动；也接入用户当前“把手拖动”绑定，包括中键。节点命中优先于同位置的单个 Head/Tail，把该次事件消费掉，避免触发普通单端点拖动或点立得放置。
- 继续使用“位置/时间拖动”两种模式及现有 Alt+T 切换。位置模式只移动横向位置；时间模式只移动接点时间。拖动开始后固定模式，拖动中按 N/切模式不改正在执行的事务；Esc、右键取消、失焦或切换文档均回滚。
- 输入框有焦点时 N 作为文字输入；播放、已有拖动事务、段选/浮动粘贴或未完成放置草稿期间不启动节点操作。关闭节点模式后恢复原有单条编辑。

### 如何识别与修改节点

1. 以真实谱面时间与 `ChartMath.SkyAt` 的端点横向区间建立候选，而不是根据屏幕上重合或 groupid 推断；必须同一 timinggroup，且都允许编辑、当前可见。不能跨时间组联动不同滚速曲线下碰巧重合的物件。
2. **完整共同截面**：前一条尾部与后一条头部的左右边界一致，显示其截面中心节点。
3. **部分接触/不同宽度**：按现有相接条件识别，在交集中心显示联动节点；横向拖动给两端同时加相同的 ΔX，各自宽度和两端相对差保持不变。只接触于一个边界点时，节点就在该接触点。不会为制造“共同中心”而把两条突然吸到相同宽度或位置。
4. **近接时间**：沿用 ±2 ms 的候选容差，但保留原时间间隔。精确相接时两端写入同一个目标时间；存在微小 gap/overlap 时两端加同一个 Δt，不能仅点击节点就偷偷对齐源时间。对近接节点在提示中显示原时间差。
5. **分叉/重叠**：同一点有多个前驱或后继时不任意选一条，也不扩展到整条链。先点选/循环候选对子并高亮双方，再开始拖动；本期每次只联动明确的一对。
6. 从拖动开始时的两个源快照计算每次预览。前条起点、后条终点固定；前条尾部和后条头部一起改变。保留各自宽度、缓动类型、精度、可选参数、显式 groupid 和 timinggroup。
7. 时间拖动先获得一个共同目标/Δt，再进行网格吸附与双方合法区间校验，不能两个端点分别取整造成缝隙。若一侧变成零/负时长、超过作者时长上限、超界，或缓动边缘交叉，整对拒绝该预览，不只接受其中一条。
8. 横向移动同样校验双方整段曲线的合法性。坐标使用已有有理数写入规则；时间拖动只写时间/时长 token，位置拖动只写对应坐标 token，避免全部参数重编码。

### 实现落点

- 新增独立的节点候选索引与编辑状态，保存两个 SourceId、头/尾标记、开始快照、History/Revision、拖动模式及鼠标捕获。索引随相关文档修订失效，不在每次 Repaint 全谱两两比较。
- 在 `StudioHotkeys.cs` / `HotkeySettings.cs` 注册 N；节点命中接入 `BuildHandles`、现有事件队列和 `MiddleHandleDrag.cs` 的捕获流程。
- 双端修改扩展 `EndpointDragMode` 的端点写入能力，使用同一份文档克隆中的一次 `EditHistory.Preview`，松开后一次提交；一次 Ctrl+Z 同时恢复两条。没有实际移动不产生撤销项。
- 特别处理 `DragNormalization` / `AuthoringSafety.BeforeCommit` 的隐式 groupid 传播：节点联动操作保留原组号，只对这类事务跳过不必要的自动改组，几何与作者校验仍执行；不能关闭所有普通编辑的校验。
- 同步失效两条物件的渲染、拾取、把手和打击特效索引，避免已修复的“编辑后光效位置错误”重新出现。

### 验收

精确相接、±2 ms 近接、不同宽度、部分横向接触、分叉选择、不同 timinggroup、不同显式 groupid、超界开关、非线性缓动分别覆盖；位置/时间模式各验证一次撤销与重做、失焦/Esc 回滚、无移动不记历史；空格预览和点立得不得偷走节点点击。逐 token 比对两个远端与未涉及的参数、第三条物件、BOM/EOL 和未知语句保持原样。

## 2. 按当前音频偏移一键导出剪歌结果

### 现状与真实偏移含义

`StudioTransport.Play` 实际使用 `audioMs = chartMs + AudioOffsetMs`。偏移只改变播放读头/延迟，没有写出处理后的音乐。取正负号时必须遵循这条公式。

| 当前偏移 | 输出处理 | 举例 |
| --- | --- | --- |
| +1500 ms | 去掉原音频前 1500 ms | 新音频 0 秒对应原音频 1.5 秒 |
| -500 ms | 在原音频前补 500 ms 静音 | 新音频 0.5 秒才开始原音频 |
| 0 ms | 提示无需处理，不生成重复文件 | 保留现状 |

令原音频为 x(t)，导出音频为 y(t)，目标是 y(t)=x(t+offset)，原音频起点之前为静音。播放导出音频时应配合 offset=0 才与当前预览对齐；若仍使用原偏移，会重复偏移。

### 用户入口与范围

“工具 → 音频 → 按当前偏移导出”。面板只展示当前源文件、已确认的偏移、裁剪/补静音说明、目标文件名和一个执行按钮。按钮先走现有输入提交校验，读取刚填写的偏移；无音频、偏移无效或播放中时给出相应状态。

本期定义为**导出新文件**：成功后给出路径与“打开所在文件夹”。不自动切换主音乐或清零当前偏移，避免仍播放原音频时失去同步，也避免影响其他难度各自的偏移。面板明确提示“使用导出音频时偏移设为 0”。这满足一键生成结果的要求；若之后增加自动替换工程主音乐，应作为单独的显式操作处理音源与多难度偏移，不能混在导出过程中。

### 输出格式与目录

建议首版固定 **PCM 16-bit WAV**，保持源采样率和声道数。直接使用编辑器已成功解码的原始 `Transport.Clip`，不使用减速播放生成的 stretchedClip，也不录制声卡输出；音量、播放倍率、打击音效不写进文件。不额外引入 FFmpeg 或有损压缩编码器。PCM16 会有一次量化，不能称为与原解码浮点样本逐位相同。

这个格式选择有当前实现依据：`SongFolderProject.Prepare` 将根目录的 MP3/OGG 视为主音乐候选；直接在同目录多写一份 OGG/MP3，会进入已有的“多个主音乐”冲突流程。WAV 作为导出结果不会成为第二份主音乐候选。独立 SPC 的 `LoadAudio` 已有 WAV 解码支持，但歌曲工程目前的主音乐仍限定 MP3/OGG，不能把 WAV 导出宣称为工程主音乐的无缝替换或本体分发格式。若最终明确要求 OGG 输出，需同时规划编码器及主音乐/附加音频声明，而非改扩展名。

目录解析：歌曲文件夹工程取 `songProject.Root`；单独已保存 SPC 取其所在目录。不得使用缓存、临时 working-copy 目录或程序安装目录作为谱面根目录。未保存的新谱面要求先确定保存目录。

命名如 `原名_offset_p1500ms.wav` / `原名_offset_m500ms.wav`，包含小数偏移时保留足够信息；文件已存在则追加编号，绝不覆盖原音频或已有导出。导出文件旁可生成小型说明 JSON，记录源文件摘要、原偏移、采样率、实际移除/补入帧数与量化误差，便于追溯。

### 处理与可靠性

- 帧偏移 n=round(offsetMs × sampleRate / 1000)，以整帧操作并同时处理全部声道；理论时间量化误差不超过半个采样帧。正偏移达到或超过音频总帧数时拒绝生成空文件；负偏移校验输出总大小。
- 分块 `AudioClip.GetData`，Unity 对象读取留在主线程，写盘可放到工作任务；有界缓冲并让出帧时间，避免一次额外分配整首歌 PCM 或长时间卡住界面。按剩余帧数读取最后一块，不能因 GetData 越过结尾而回绕复制片头。
- 对 PCM16 做明确的裁幅与量化，保留声道交织和采样率，不做响度归一化、淡入淡出或采样率转换。
- 写入目标目录内的唯一临时文件，填好 RIFF/WAV 头、长度、声道和采样率后，再用已有 `WaveReader`/独立头校验确认输出可读取，然后发布成最终文件。
- 取消、磁盘不足、读权限/写权限失败时只清理本次临时文件。源文件不删除、不改名、不覆盖；源文件和谱面保存仍相互独立。
- 绑定开始时的音频、路径、工程、难度和偏移快照。处理中更换工程/难度/音源或修改偏移则取消/拒绝过期完成通知，不能把旧任务的文件放入新工程。
- 预计大小超过当前 WAV 读取上限 256 MiB 时提前提示并阻止首版输出，不生成编辑器自己无法重新读取的结果。以后如需长音频，应先提升读取/流式处理能力。

### 实现落点及验收

新增内置音频导出面板与任务状态、分块 PCM 导出器；通过 `StudioTransport.Clip` 获取原音频，复用 `StudioBootstrap` 的已确认路径和工程 Root。与内置快速工具一起注册，不作为外置脚本特例，不修改游戏判定或谱面时间。

测试 +1500/-500/0 ms、小数毫秒、单声道/双声道、不同采样率、短于偏移的音频、同名结果、中文路径、取消及写盘失败。验证帧数、静音区、首个有效样本及 PCM 量化误差；原音频 SHA-256 前后一致，谱面时间与 offset 没有隐式变化，四难度切换后没有错误关联；重新打开歌曲文件夹不因导出文件出现双主音乐冲突。

## 3. 随 ExternalTools 提供适中长度的工具编写说明

### 现状与原因

副本已存在 `ExternalTools/README.md` 与 `PROTOCOL.md`，工作节点还有 `studio_icon_work/EXTERNAL_TOOLS.md`。因此不是从零发明协议，而是整理成能直接照着写工具的指南，并修正旧说明。

已确认旧 `PROTOCOL.md` 有一处过时表述：它把 `skySources[].grid` 描述为“物件所在时间组内网格”，当前 `PrepareToolGrid` 实际使用**主界面当前时间组与细分**，并提供 `gridDivision`、`gridGroup` 和 `grid`。照旧文档实现会在变 BPM/跨组情况下得到不同结果。另当前发布脚本按三个白名单工具子目录复制，没有显式复制 ExternalTools 根目录说明，文档容易在新包中遗漏。

### 交付方式与篇幅

计划以 `ExternalTools/工具编写指南.md` 为主要入口，正文约 1500～2500 个中文字，附一个可复制的最小示例。`README.md` 放短入口链接；`PROTOCOL.md` 保留完整字段参考并同步修正。更新 `EXTERNAL_TOOLS.md` 引用同一套定义，注明文档核对的插件节点与协议版本 1，不只用旧 1.0.47 标题代表当前接口。

源码中为根目录文档提供独立 Docs 目录；安装和未来打包显式复制这些 Markdown。示例放在文档代码块，或非扫描的示例资料目录，避免成为第四个默认启用工具。保留用户已有工具；默认分发工具仍为 MakeRain、GradientTiming、TimingSplit。

### 指南必须讲清的内容

1. **目录结构**：`ExternalTools/MyTool/tool.json`、同目录 `Tool.ps1`，可选 `defaults.json`、辅助代码与 README。目录名严格等于 id；id 以字母开头，后续只允许字母、数字、下划线。
2. **清单**：version=1，name/nameEn，script 为存在的同目录 .ps1 文件；新工具使用 output="spc"。列出 order、description、selection、capture/captureKind、gridField、groupMode 的含义与适用条件。
3. **参数控件**：time/integer/number/text/file/bool/choice；fields 最多 30 个，key 唯一，choice 必须包含有效默认选项。values 的值是字符串，工具自己按固定小数点规则解析。time 是 0～86400000 的整数毫秒。
4. **调用约定**：Windows PowerShell 通过 `-RequestPath` / `-OutputPath` 调用脚本，工作目录是工具目录。成功退出码 0；失败写 stderr 并返回非零；实际结果写文件，stdout 仅作日志。UTF-8 编码和含空格路径必须正确处理。
5. **请求字段**：version/tool/values、document/hasBom、rows、selection、capture、currentTime/currentGroup/targetGroup、range，以及 grid 相关字段。SourceId 是本次文档会话的稳定 ID，不是源行号，也不能跨工程长期缓存。捕获只是快照，不能把旧 capture 的 ID 当作当前文档替换目标。
6. **主界面网格**：优先使用请求提供的网格时间，含当前组 BPM 变化与相位；gridField 是主界面细分的只读映射，不从旧工具偏好重算。按数量模式不生成网格快照，工具要按自身声明分支处理。
7. **输出**：SPC 原文用于追加；JSON version=1 的 operations 支持 append/replace/delete。解释 scope="$target"、基础组空字符串、指定组名与 null 完整组块；replace/delete 使用请求 rows 的 sourceId，建议附 expected 核对原行，同一源行一批只能改一次。
8. **行为边界**：脚本只生成 OutputPath 结果，不直接写当前谱面。结果先在克隆文档校验，成功才一次事务提交，Ctrl+Z 撤销、Ctrl+S 保存；未知语句可保留但不代表编辑器或官方本体实现了其语义。timinggroup/noinput 等扩展注明目标壳子限制。
9. **限制和报错**：120 秒超时，输出 ≤8,000,000 字节、≤64000 条操作/变更行，选中 SkyArea 单条网格≤4096点，通用范围网格≤10000点；非法几何/分组、运行时文档修订或当前组/细分变化导致取消。不要把这些字节限制笼统写成 MiB。
10. **最小示例与调试**：给出完整 tool.json 和十几行 PowerShell，用一个 time 字段生成一条 `track(time,1)` 到目标组，附真实 request 样例、输出预期和独立调用命令；再给一个按 sourceId/expected 替换的 JSON 小例子。说明可写 `OutputPath + ".info.json"` 的 message/segments 摘要，摘要不能代替正式输出。

### 验收

在干净隔离副本中只照着文档复制最小工具，确认能发现、填写参数、运行、一次撤销和手动保存；故意制造清单 id 错误、非法输出、过期 SourceId、超时、网格切换，验证文案与程序实际行为一致。检查安装目录和未来压缩包都包含根目录指南，且没有增加默认工具、个人 pattern.json 或 ScriptCache。
