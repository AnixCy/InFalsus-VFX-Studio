# 渲染与效果组合

编辑层的效果片段、参数和关键帧不与 GPU Pass 一一对应。可在同一底图材质中组合的功能，合并参数后绘制一次；确实需要图像中间结果的处理，再使用独立 Pass。

## 当前实现

背景栏只管理图片。效果库提供 36 个底图控制项和 12 个原始材质组合，包括 Ephemeral、Feedback、切片、径向缩放、噪声和图案变形。前两项固定排列在效果库顶部，并可搜索名称。

这些控制项仍调用已有编译 Shader，直接采样当前底图，没有改成逐项全屏处理。控制实例分别保存区间、启停、数值和关键帧；渲染器将兼容实例的值合并到同一背景材质。本轮 GPU 对照确认流场与嵌套旋转组合等于原材质输出，未增加后处理 Pass。

底图效果的“效果强度”插值其控制参数，不是额外图像混合 Pass。普通后处理仍可单独执行，并保留自己的图像混合强度。

当前复用的是多套已经编译的 GPU 程序。不同原始组不能直接互相拼接；重叠时选用时间轴下方的组，并在预览中提示。部分组内部也有互斥模式，例如一个主模式可以与流场组合，但其他主模式不能任意同时开启。此限制属于当前资源与适配，并非 Unity 或 GPU 的通用限制。

新增工程用 `effect.background-controls` 声明该语义；旧运行端应明确拒绝，不能将控制节点误当作全屏 Shader。旧工程原背景及动画仍按原方式读取，输入文件不自动迁移或改写。

## 原生实现依据

已核对的示例专用场景包含背景 Quad、原图、两类噪声贴图、私有 BG/PP 材质和参数时间线。BG 具有十个像素变体：五个主状态分别可叠加流场。控制器避免未编译的组合同时启用。

流场和嵌套旋转按顺序改变 UV，随后执行四次原图取样并混色；嵌套并不读取历史帧。全屏故障与冲击则在相机颜色之后处理，按需执行一次效果绘制及写回。一个 Pass 不代表一次纹理采样，也不能凭 Pass 数推断实测帧时间。

## 后续融合方向

统一 Shader 函数库应区分 UV 变换、像素颜色运算、多邻域采样和图像合成。兼容 UV 与颜色运算按确定顺序合并，选择少量预编译变体；帧内关键帧求值只更新参数。模糊等需要前序结果的功能按依赖决定中间图，避免机械地为每个编辑片段增加 Pass。

单个大型源码文件不保证最低成本。动态分支可能影响执行与寄存器资源；静态变体也会增加构建、内存和预热规模。以目标设备上的帧时间、带宽及 Shader 成本决定拆分。本轮没有建立统一 HLSL 函数库，也没有承诺全尺寸性能。
