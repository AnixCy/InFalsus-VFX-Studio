# 基础设施状态与接入顺序

本文是开发审查与交接手册，列出当前已有能力、缺口和验证边界。供创作、宿主和运行端开发者使用；不将未接入的底层接口当作编辑器功能。

## 当前交付边界

- 编辑器插件及玩家原型现为 **0.9.0**，完整歌曲 ZIP、保存的 Studio 源工程编译、随谱身份发现和两种 Loader 入口已接通，见 [曲包手册](CHART_PACKAGES.md)。音频驱动及制作工程资源搬迁仍未接入应用，不随玩家运行包分发。
- 参数、事务、撤销、时钟及资源归属已存在，继续复用。无需另建一套编辑模型或运行播放器。
- 音频驱动是制作端独立库；只有烘焙后的普通参数曲线进入玩家数据。玩家不新增 DSP、解码器、后台服务或编译器依赖。
- 参数曲线正确、资源可加载和审美达标是不同的验收项目。此前程序化背景 demo 的效果基线获用户认可；新的音频 demo 只有数值验证。

## 无需视觉验收即可复用的新增接口

详见 [音频驱动契约](AUDIO_REACTIVE.md)。

1. `BandAnalyzer.GetCacheKey`：已知解码内容指纹后，在运行 FFT 前计算磁盘查找键。
2. `AudioAnalysisStore`：宿主提供 JSON codec；读出 `Missing / Hit / Invalid`。无效派生缓存可以重建，真实权限/磁盘/锁冲突传播为 I/O 错误，不伪装成缓存未命中。
3. `AudioBakeBatch`：输入人工通道快照与驱动计划，返回独立通道副本和逐参数误差/关键帧统计。未驱动的颜色、资源选择等通道原样保留，不改工程或撤销栈。
4. `AddonPackage.MaximumDocumentBytes` 与源码导出器校验：运行端和导出端共用 4 MiB 上限，按真实 UTF-8 编码大小判断，拒绝后保留原项目并清理自有暂存目录。

这些独立组件不是新的应用层，不迁移或覆盖已有 demo、缓存及工程；0.8.0 透明度控件与编辑器插件更新单独记录。

## 后续接入顺序

下一步优先处理实际创作中的数据往返，而非扩展效果数量：

1. **资源清单与搬迁**：底层已完成声明资源复制、相对路径与新目录回读，详见 [创作工程手册](CREATOR_WORKSPACE.md)。后续只做现有工程字段的适配，不能把整套编译 workspace、缓存或隐藏绝对路径视为已迁移。
2. **驱动 recipe 与原人工曲线共同保存**：底层已完成来源身份、稳定轨道和独立派生输出。后续宿主必须保持 ManualProject 权威性，不能把 Bake 输出重新当作人工输入。
3. **宿主异步接入**：后台使用稳定 PCM/工程快照；提交前核对工程 ContentId、请求代次和绑定身份，丢弃过时结果。复用现有 AuthoringSession 版本检查与一次事务，不先造第二套并发框架。
4. **资源兼容与导出预检**：在扩展游戏支持前，保留明确的支持列表、整包大小与材质目标诊断；本次只补大小边界，没有承诺通用 Shader 已可导出。
5. **UI 与实际画面验收**：再处理参数旁驱动入口、包络预览、取消/重试提示和创作工作流。当前无需用户立即测试。

资源搬迁和来源保存已按后续授权完成独立基础设施；其余事项等待具体接入需求。资源搬迁尚无 UI，也未重构 Shader 管线。

## 自动验证与冻结的人工验收项

```powershell
& .\scripts\Check-Infra.ps1 -OutputDirectory '<新的检查目录>'
```

需要制作端 .NET SDK 9，不启动 Unity 或游戏，不播放音频，不使用截图/视觉工具。验证 cache 内容校验、损坏修复、锁冲突、编码器失真、取消、预算、批量参数与原数据隔离，以及超限/多字节/边界大小导出回读。

单独的音频数值/demo 检查使用 `Check-AudioReactive.ps1`；既有 addon 检查仍为 `tests/Addon.Checks`。只运行和变更相关的夹具，记录本次结果，历史计数不冒充本次验证。

独立创作容器使用 `Check-Workspace.ps1`；其中原目录断开、资源/来源往返与烘焙失效可纯数值验证，实际链接权限不足或创建失败会单独记录跳过，不算已验收。

保留为待验收：新音频 demo 的听感/画面、驱动 UI 的操作、多个素材迁移后的实际创作体验、跨设备性能和复杂游戏转场。无需用户现在反馈，也不会据此自动扩大支持声明。当前测试及未验收范围见 [VALIDATION.md](VALIDATION.md)。
