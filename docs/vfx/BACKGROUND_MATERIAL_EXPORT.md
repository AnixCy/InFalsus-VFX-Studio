# 通用背景材质导出

0.10.0 将背景材质、依赖资源与动画纳入原有整曲包导出。导出器按资源和参数契约处理，不维护具体效果名称白名单。Feedback / Ephemeral 是验证用例；它们仍使用原始编译材质，不在导出时换成简化近似算法。

## 支持范围与操作

在演出视图沿用“导出曲包”。独立背景材质、原始背景预设和从背景材质拆出的控制项都走相同路径；同一组控制项合并到一个源材质，区间外恢复输入背景。参数、关键帧、缓动、透明度权重、启停、叠放顺序和关键字沿用预览规则；不同组之间按现有叠放优先级选择，不自动拼接多个全屏处理。

自定义页新增“新建背景…”与“新建后处理…”两个明确入口。背景模板提供对象顶点、UV、原生 `_Color`、Geometry 队列和深度写入；修改 Shader 并保存，参数仍自动发现并可打帧。整曲导出时将成功预览对应的源码编译为游戏目标材质，首次可能需要选择匹配的 Unity Editor；后续相同源码复用缓存。编译错误、源码正在更新或预览尚未跟上新构建时拒绝发布，不拿另一版源码替代当前预览。

自定义游戏资源目标是 Unity 6000.3.9f1 / Windows x64 / 当前游戏色彩空间。构建保留源 Shader 和同目录 `.hlsl` / `.cginc`；不改工程源码。只有编译包、没有关联源码的自定义预览效果，无法自动重编译为游戏目标，需要重新关联源码。原始背景缓存已经是游戏资源，不要求重新安装 Unity 才能导出它。

模板自身需要符合背景绘制契约：一个材质 Pass、对象空间顶点、原生场景颜色和正确深度。屏幕三角形、历史帧、额外摄像机或多通道效果属于另一种渲染阶段，不能仅改名为背景后导出。没有 `_MainTex` 图像入口的纯程序化背景可导出，但需要清空背景图片；不会默默丢掉图片。

原先通用背景的融合色彩导出继续保留。原始/自定义背景材质路径目前只旁路恒等的默认色彩项；非恒等的屏幕后处理会明确阻止导出。可直接编辑背景 Shader 已暴露的颜色等参数。这是渲染阶段的边界，不是按效果名逐个增加导出适配。

## 玩家安装与成本

复杂背景包需要 **0.10.0** 运行包。玩家更新一次对应 Loader 的运行 DLL，之后仍将歌曲 ZIP 解压到 Charts，不需要 Unity、源码、编译器或新服务。基础背景包保留旧能力契约；旧玩家会明确拒绝不认识的新材质语义。

一个背景控制项不等于一个 GPU Pass。游戏预加载包内引用的有限材质，任意时刻只绑定一个背景材质；同源项共享实例，不分配后处理画布或历史帧纹理。常量不重复设置，关键字只在变化时切换，时钟只更新当前材质；Shader 属性与关键字索引在准备阶段缓存。切换依然遵守原背景的所有权和退出恢复规则。

Shader 内部采样和运算成本由效果本身决定。复用原始材质不表示任意强度或任意 Shader 都免费；没有本轮真实游玩 FPS 或低配置帧时间结论。当前实例预算为一个输入背景、最多 16 个源材质组、64 个逻辑控制项。只有被引用的 Bundle 和文件依赖进入包，不复制完整本地效果库。

## 数据和代码入口

- `BackgroundBindingDocument`：源资源身份、暴露参数及中性值、图像入口、关键字与互斥组；是数据，不携带用户 C#。
- `BackgroundMaterialPlan`：预览与游戏共用的选择、插值混合、区间及关键字求值。索引只构建一次，采样复用缓冲区；随机定位不积累图像历史。
- `EffectLibrary.BackgroundBinding.cs`：从现有效果目录构造派生描述；不改作者的工程与关键帧。特定旧 Shader 的已知变体组记录为目录元数据，运行/导出代码无需识别其效果名。
- `MaterialBackgroundExport.cs`：通用资源发布；Bundle 使用内容名称和完整清单 SHA-256，相同资源去重。保留文档/图片预算、相对路径、暂存发布和失败清理。
- `PreviewPlugin.MaterialExport.cs`：制作端源码目标构建、源码/预览一致性检查和缓存。构建工具与 Unity 只在创作端，不进入玩家包。
- `UnityRenderBackend.Background.cs`：读取 Shader 或 Material 入口，按类型更新参数并将选定材质交给原生背景目标；不注册后处理阶段。

运行 JSON 的每个相关节点带可选 `BackgroundBinding`，包声明 `background.material-plan.v1`。背景控制项保留其逻辑节点和时间范围，物理资源按 SourceId 合并。场景透明度仍由 `scene.opacity.v1` 单独处理。

新算法放进背景 Shader 并暴露参数即可沿用此路径；新增历史帧或其他渲染阶段时，应另行声明能力与预算。不会通过为每个效果写专用导出函数来扩展。

数值契约检查位于 `tests/BackgroundMaterial.Checks`。Studio 可用 `Check-PreviewRuntime.ps1 -ChartPackSource '<合成曲包>' -MaterialSource '<测试背景源码工程>'` 检查真实构建与导出；游戏检查沿用带所有权标记的物理副本，额外提供 `-MaterialExpectations '<测试期望 JSON>'`。实际覆盖与待验收项见 [VALIDATION.md](VALIDATION.md)。
